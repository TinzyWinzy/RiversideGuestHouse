1. ARCHITECTURE (LOCKED)
Stack: Vite + React + TypeScript | Pre-rendered public routes (vite-plugin-prerender or Vike) for /, /accommodation,
/location | SPA /admin/* | Firebase (Firestore, Auth + custom claims, Functions, App Check reCAPTCHA v3, Storage) |
Vercel hosting (production + preview). Dev and prod use separate Firebase projects.
Principle: WhatsApp is the communication channel; Firestore is the operational record. All writes via Cloud Functions;
public client has zero direct writes. Funnel: Discover -> Enquire -> Capture -> Respond -> Book -> Manage.

2. FIRESTORE SCHEMA (NORMATIVE)
All docs carry createdAt/updatedAt (serverTimestamp) unless noted. Phone stored E.164. Dates ISO strings, checkOut > checkIn.

settings/property (single doc):
  name, description, location{addressText, lat, lng, placeId|null, searchUrl, dirUrl}, facilities[],
  contactPhone, contactEmail|TBD, whatsappNumber, socialLinks{}, startingPriceText, longStayMessage|TBD,
  navigationLandmarks, updatedAt
  Seed: name "Riverside Guest House", addressText "22418 Riverside Park, Ruwa Zimbabwe", lat -17.876727, lng 31.228801,
    placeId null, searchUrl "https://www.google.com/maps/search/?api=1&query=-17.876727,31.228801",
    dirUrl "https://www.google.com/maps/dir/?api=1&destination=-17.876727,31.228801",
    contactPhone "+263774114599", whatsappNumber "+263774114599",
    startingPriceText "From US$20/night", navigationLandmarks "Near KFC/Steers food courts, Mutare Road, Ruwa".

accommodations/{id}:
  type [ensuite|ordinary], name, description|TBD, capacity|TBD, rate, currency "USD",
  amenities[]|TBD, images[]|TBD, active, createdAt, updatedAt
  Seed: ordinary-room {type ordinary, name "Ordinary Room", rate 20, currency USD, active true};
        ensuite-room {type ensuite, name "Ensuite Room", rate 30, currency USD, active true}.
  Public "from" price = min(rate) over active docs, never hard-coded.

guests/{e164phone}:
  name, phone, email?, notes, createdAt, updatedAt. Keyed by normalized phone to reduce duplicates.

enquiries/{id}:
  guestId, accommodationId, checkIn, checkOut, partySize, longStay bool, message, status,
  source "web", quotedRate, currency, quotedAt, idempotencyKey, createdAt, updatedAt.
  status: NEW|CONTACTED|PENDING|CONFIRMED|COMPLETED|CANCELLED.

bookings/{id}:
  enquiryId (unique, 0..1 per enquiry), guestId, accommodationId, checkIn, checkOut, partySize,
  status [PENDING|CONFIRMED|COMPLETED|CANCELLED|NO_SHOW], notes, quotedRate, currency, createdAt, updatedAt.

users/{uid}: name, email, role [ADMIN|MANAGEMENT], active, createdAt. Role mirrored to Auth custom claims.

auditEvents/{id}: actorId, entityType, entityId, action, timestamp, metadata. Create-only, no update/delete.

Relationships: accommodations 1--< enquiries/bookings; guests 1--< enquiries/bookings; enquiries 1--0..1 bookings;
users 1--< auditEvents. References are plain ID fields (guestId, accommodationId, enquiryId).

Indexes (firestore.indexes.json):
  enquiries: status ASC + createdAt DESC. bookings: status ASC + checkIn DESC. Single-field active==true needs no composite.

Rules summary (firestore.rules normative file):
  settings/property, accommodations(active only): public read, no public write.
  enquiries/bookings/guests: management+ read/write only; public create denied (must use createEnquiry function).
  users: self-or-admin read, admin write. auditEvents: admin read, functions-only create.
  UI gating is never sufficient; claims + rules + function checks enforce.

3. CLOUD FUNCTIONS CONTRACTS
3.1 createEnquiry(payload) -> {enquiryId, whatsappUrl}
  In: guest{name, phone, email?}, details{accommodationId, checkIn, checkOut, partySize, longStay, message?},
      idempotencyKey, appCheckToken.
  Logic: verify App Check; rate-limit 5/IP/hr + 3/phone/hr (429 + optional captcha on abuse); validate E.164 phone,
    checkOut>checkIn, partySize<=capacity, accommodation active; guest upsert in transaction (key = E.164 phone);
    snapshot rate/currency/quotedAt from accommodations; create enquiry status NEW (idempotent on idempotencyKey);
    build whatsappUrl server-side; dispatch onNewEnquiryNotify; return {enquiryId, whatsappUrl}.
  TS types live in functions/src/enquiry.ts (to be scaffolded).
3.2 convertEnquiryToBooking(enquiryId, overrides{checkIn?, checkOut?, partySize?, notes?}) -> {bookingId}
  Guards: enquiry must be CONFIRMED or PENDING; exactly one booking per enquiryId (transaction); copies
    guestId/accommodationId/dates/partySize + agreed quotedRate/currency (long-stay discount applied here manually for MVP).
3.3 updateEnquiryStatus(enquiryId, nextStatus, notes?) — allowed:
  NEW->CONTACTED|CANCELLED; CONTACTED->PENDING|CANCELLED; PENDING->CONFIRMED|CANCELLED;
  CONFIRMED->COMPLETED|CANCELLED. All else rejected. Writes auditEvents.
3.4 updateBookingStatus(bookingId, nextStatus, notes?) — allowed:
  PENDING->CONFIRMED|CANCELLED; CONFIRMED->COMPLETED|CANCELLED|NO_SHOW. All else rejected. Writes auditEvents.
3.5 onNewEnquiryNotify (onCreate enquiries): email to mgmt address immediately (olv: must survive failure — enquiry
  persistence never depends on notification success). checkStaleEnquiries cron every 30 min: NEW older than 2h ->
  WhatsApp nudge hook to mgmt number. NFR-010.

4. WHATSAPP HANDOFF
Server-built: https://wa.me/263774114599?text=<url-encoded>. Body template:
  "Hello Riverside Guest House,\n\nI would like to enquire about accommodation.\n\nRef: ENQ-{shortId}\nName: {name}\n
  Check-in: {d} Check-out: {d} Guests: {n} Room: {roomName} Long stay: {Yes/No}\n\nPlease confirm availability and pricing."
Persist-before-redirect enforced; if WhatsApp unavailable, enquiry stays in Firestore and UI offers retry + manual
"Message us: +263774114599" fallback. Never place email/phone in URL beyond message body (SAD 16).

5. MAPS / NAVIGATION
Primary (works today, per capesee pattern): searchUrl maps/search/?api=1&query=-17.876727,31.228801 and
dirUrl maps/dir/?api=1&destination=-17.876727,31.228801. If a GBP placeId is supplied later, append
&destination_place_id={placeId} to dirUrl to surface reviews/photos. Offline/low-data fallback: show
navigationLandmarks text. Property model keeps placeId nullable so schema needs no migration when it arrives.
